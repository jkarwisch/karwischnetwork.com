MANAGEMENT SYSTEM MIGRATION

AMS Management System Migration for a Fiber Broadband Provider

Primary hands-on engineering for an in-place Nokia AMS migration across multiple maintenance windows.

Project Type
FTTH Broadband Access Network Management System Migration
Customer Type
Fiber Broadband Internet Provider
Technologies
Nokia AMS, ISAM FX, Red Hat Linux, High-Availability Clustering, Geographic Redundancy

Project Overview

Served as the primary hands-on deployment engineer for an in-place software migration of a Nokia AMS management platform supporting a fiber broadband access network.

The deployment utilized high-availability server clusters with geographic redundancy, requiring careful planning, laboratory validation, and coordinated execution across multiple maintenance windows.

The project involved collaboration with customer engineering and ISP teams to minimize operational disruption while upgrading the management platform and verifying system functionality.

CHALLENGE

Technical Challenges

High-Availability and Geographically Redundant Architecture

The AMS environment utilized high-availability clusters and geographic redundancy, increasing the complexity of migration planning, testing, and execution.

Laboratory equipment availability did not permit a complete replication of the production environment. However, a minimal high-availability cluster and geographic redundancy configuration was established to support migration testing.

Third-Party Network Dependencies

During migration, the team identified additional connectivity requirements involving network address translation (NAT) and load-sharing equipment used to communicate with AMS.

The relevant configuration settings were not automatically carried forward into the upgraded AMS application, requiring configuration adjustments during the maintenance window to support the existing network architecture.

APPROACH

Technical Approach and Contributions

As the primary hands-on deployment engineer, responsibilities included:

  • Collaborating with customer and engineering teams to develop the migration plan.
  • Establishing a representative laboratory environment with a minimal high-availability cluster and geographic redundancy configuration.
  • Developing and testing the migration Method of Procedure (MOP) using the available laboratory equipment.
  • Reviewing the MOP with the customer and other engineering team members before execution.
  • Executing the migration across multiple scheduled maintenance windows to minimize operational disruption.
  • Identifying and addressing configuration requirements associated with third-party NAT and load-sharing components.
  • Performing Acceptance Test Procedures (ATP) after each maintenance window to validate system functionality and operational readiness.
OUTCOME

Results and Outcomes

All planned acceptance tests passed successfully following each migration maintenance window.

The project demonstrated the ability to plan, test, and execute complex management-system migrations involving high-availability clustering and geographic redundancy.

It also reinforced the importance of understanding third-party network dependencies and adapting migration procedures when unexpected configuration requirements arise.
